EPSG 代码究竟标识什么

EPSG 代码是一个短号码，用来命名 EPSG 大地参数数据集（EPSG Geodetic Parameter Dataset）中的一条记录——这是由 IOGP 维护的坐标系统、基准、椭球、单位与变换的注册表。 它起源于欧洲石油测量组织（European Petroleum Survey Group），四个字母由此而来；如今它是 GIS 软件、GNSS 接收机、网络服务和测量仪器声明「我说的是哪套坐标」的通用语言。

代码写作 授权机构:代码，例如 EPSG:4326 是 WGS 84 上的经纬度， EPSG:32617 是 WGS 84 / UTM 第 17 带（北）。代码标识的是一整套坐标系统而不是 一个地点，所以同一片场地可以同时被几个代码如实描述：位置是同一个，挂在上面的数字不是。

最重要的推论是：不知道代码，一对坐标就没有意义。630084.301, 4833438.586 在 UTM 17 带里是一个完全合理的位置，按任何其他代码去读就是大西洋上的另一个点。

四类代码

绝大多数代码落在以下四类之一，打开文件之前先判断类别，就能预判数字长什么样。

类别坐标是什么例子
地理 2D 某基准上的经纬度，单位是度，不涉及投影。 4326 WGS 84 · 4269 NAD83 · 4490 CGCS2000
投影坐标 平面上的东坐标与北坐标，单位米或英尺，只在投影设计覆盖的范围内有效。 32650 UTM 50N · 27700 英国国家格网 · 2205 Kentucky North
地理 3D 经度、纬度加椭球高——GNSS 接收机的原始输出。 4979 WGS 84（3D）
高程系统 只有高程，从一个指定的高程基准起算，而不是从椭球面起算。 5703 NAVD88 高程 · 5773 EGM96 高程

复合代码把平面系统和高程系统捆绑在一起——例如某个州平面分带配 NAVD88 高程， 这正是绝大多数测量成果的实际形态。3D 代码里的椭球高与高程代码里的海拔之间的差异由大地水准面 决定，详见大地水准面与椭球面（英文）。

4326 还是 3857？最容易踩的一对

这两个代码覆盖了世界上大部分数据，也最常被混为一谈，因为名字里都带 WGS 84。 它们根本不是一类东西：4326 是地理坐标——经纬度的度；3857 是投影 坐标——东坐标与北坐标的米，原点在赤道与本初子午线交点。

3857 内部还有第二重陷阱。真正的墨卡托投影把椭球面搬到平面上，而 Pseudo-Mercator 用一个 半径 6 378 137 米的球体替代了椭球。这让计算更简单、瓦片是正方形，但也意味着它的北坐标与 真正的椭球墨卡托（如 3395）系统性不同。

也就是说，北纬 30° 处两者的北坐标相差约 21 公里，北纬 60° 处相差约 37 公里。两者都没有错， 只是回答的问题不同；但如果文件声称是 3857 而实际按椭球计算（或反过来），就会出现 公里级的偏差，怎么复核测量数据都对不上。

Pseudo-Mercator 还会在离赤道越远处夸大距离和面积：30° 处长度比约 1.15，45° 处约 1.41， 60° 处达 2.0。绝不要在 Web Mercator 图层上量面积和距离，应换到 州平面或 UTM 分带这样的投影坐标系， 或先转回经纬度再在椭球面上计算。

长得像但不是一回事的代码

大多数坐标事故不是笔误，而是两个代码恰好差一个「看起来合理」的量。

单位是代码的一部分，代码分段正是为了表达它。NAD83 的州平面分带按单位分成两段： 26900s 和 32000s 段以米计，2200s 段是英尺版本——上表中 53 个用美国测量英尺、15 个用国际英尺。 把米制分带按英尺读，所有坐标放大 3.28 倍，看见一次就忘不掉，没看见之前毫无察觉； 两个英尺带互相读错更隐蔽，百万分之二在到达边界之前什么也看不出来。

如何确定一个陌生地区的 EPSG 代码

  1. 先问这批坐标是做什么用的。国家测绘成果通常用国家格网；州或省往往有自己的分带； 与全球数据集挂钩的项目通常在 UTM 里。用途比任何搜索都更快缩小范围。
  2. 在元数据里找基准。WGS 84、NAD83、ETRS89、GDA2020、CGCS2000、NAD27 各自通向一族 代码，差别通常写在文件头、服务能力文档或图纸标题栏里。
  3. 查单位。米与英尺把每一族代码一分为二。北坐标约 5 000 000（米）是 UTM 型坐标； 约 16 000 000 则很可能是英尺，或是有自己原点的国家格网。
  4. 看东坐标的数量级。约 500 000 意味着中央子午线在附近的 UTM 型分带； 十万位的六位数东坐标配很小的北坐标，多半是带独立原点的地方格网。
  5. 在本页按地区名搜索。输入州、国家或分带名（英文），候选代码连同单位与适用范围一起 出现，通常足以锁定与数据覆盖范围匹配的那一个。注意检索需用注册表原文（英文）。
  6. 用一个已知点确认。把一个可以独立核实的坐标——测量标志、纪念碑、知名地标—— 转换一次，看落点是否合理。一个确认点胜过任何数量的阅读。

EPSG 代码与 Esri WKID

Esri 软件在 EPSG 之外使用自己的 well-known 标识。两者有很多一致——Esri 也把英国国家格网 叫 27700——但也有相当一部分不一致，两个注册表在同一号码下并不总是描述同一件事。

  • Web Mercator。Esri:102100 及其前身 Esri:102113 描述的都是 EPSG 的 3857， 只是授权机构不同。
  • 北美州平面。Esri 把 102000s 段的号码分给州平面分带，其 EPSG 对应代码在 2200s 与 26900s 段——102603 与 2205 可以在不同注册表里描述同一个 Kentucky 分带。
  • 已弃用条目。两个注册表都会退役代码。一个在某个软件里仍能用的代码，可能已在 注册表里标记为弃用——这正是值得查一次定义、而不是永远相信文件里那个号码的原因。

当两个系统不一致时，最稳妥的做法是传递完整定义——WKT 或 PROJ 字符串——而不是一个号码， 因为号码离开授权机构什么也不是。

常见问题

什么是 EPSG 代码？

EPSG 代码是一个短号码，命名 EPSG 大地参数数据集中的一条记录——这是由 IOGP 维护的坐标系统、基准、椭球、单位与变换的注册表。代码写作「授权机构:代码」，例如 EPSG:4326 是 WGS 84 上的经纬度，EPSG:32617 是 WGS 84 / UTM 第 17 带（北）。

EPSG 4326 和 3857 有什么区别？

4326 是地理坐标：WGS 84 上的经纬度，GPS、GeoJSON 和 KML 用的都是它。3857 是投影坐标：米制的东坐标与北坐标，网络地图瓦片在用。两者不可互换，而且 3857 是球面墨卡托，北坐标与真椭球墨卡托在北纬 30° 处差约 21 公里、60° 处差约 37 公里。

UTM 应该用哪个 EPSG 代码？

WGS 84 上北半球分带是 32601 到 32660，南半球是 32701 到 32760，所以 UTM 第 17 带北是 32617、南是 32717。北美的 NAD83 用 26901 到 26923，欧洲的 ETRS89 用 25828 到 25838。

怎么查某个州平面分带的 EPSG 代码？

在本页搜索州名，不要猜号码。NAD83 州平面按单位分段：26900s 与 32000s 段是米制，2200s 段是英尺制（多为美国测量英尺）。例如 Kentucky 北带是 2205（英尺）、南带是 26980（米）；California zone 3 米制是 26943、美国测量英尺是 2227。还要当心相邻段：26901–26923 是 NAD83 UTM 分带，根本不是州平面。

为什么同一个地区有好几个 EPSG 代码？

因为代码标识的是一整套坐标系统，不是一个地点。同一个位置可以在 WGS 84、NAD83 或 NAD27 上描述，可以用米或美国测量英尺，可以放在地方分带或 UTM 分带里——每种组合都是注册表里独立的一条，各有各的代码。

EPSG 代码和 Esri WKID 一样吗？

经常一样，但不总是。许多 Esri 空间参考引用与 EPSG 相同的号码，另一些用 Esri 专属标识：Esri:102100 和 Esri:102113 描述的都是 EPSG 的 3857，若干州平面分带在 Esri 里是 102000s 段的号码。把两者当作相等之前，先确认文件或服务引用的是哪个授权机构。

EPSG:32617 这种写法是什么意思？

冒号前是维护定义的授权机构，冒号后是该机构内的代码。EPSG:32617、urn:ogc:def:crs:EPSG::32617，以及 GIS 导出的 WKT 或 PROJ 字符串，是给同一个系统起名字的三种方式。

本页的 EPSG 数据来自哪里？

代码、名称、单位、适用范围与投影参数通过 PROJ 库读取自 EPSG 大地参数数据集，没有手工录入，已弃用的条目也不会以现行面目出现。你看到的是为测绘工作挑选的参考子集，不是整个注册表。
