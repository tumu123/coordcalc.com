关于 CoordCalc

CoordCalc 是一组共十七个计算器和十三篇中文教程，覆盖一项测量工作周边的全部算术：坐标转换、 距离与面积、单位与地籍、坡度、比例尺、曲线与导线。它免费、完全在你的浏览器里运行， 写给的是需要拿出一个经得起追问的数字的人——核对图纸的测量员、正在解题的学生、 查看 CAD 文件的工程师、梳理基准的 GIS 技术人员。

为什么做这个站

大多数坐标问题难的不是数学，而是记账：该用哪个基准、哪个投影带、哪种英尺， 以及三个看起来一样其实不一样的代码谁是谁。网上有很多转换器只给一个结果、别的什么都不说， 而它们出错的后果总是一样的——一个错得理直气壮的数字，没人质疑它，因为它是某个网站给出的。

所以这里的每个计算器都做两件事：算出结果，并说明它假设了什么——用哪个椭球、 假原点在哪里、单位习惯是什么、两种英尺差在哪里、投影面积为什么不是地表面积。 教程则更进一步，讲的都是算术周边真正会遇到的问题：UTM 坐标怎么读、 MGRS 往返换算为什么会差出一米、椭球下面的似大地水准面在做什么、 美国测量英尺为什么一直活到 2023 年才退场。

计算是怎么构建的

所有工具背后是同一个大地测量库。它是无依赖、不联网的原生 JavaScript， 写法取的是保守的那一路：横轴墨卡托投影用公开的级数式；反算不是套一个截断的反向公式， 而是对同一个级数做牛顿迭代求解；距离用 WGS84 椭球上的 Vincenty 反算， 对近对跖点回退到球面算法；挪威与斯瓦尔巴的投影带特例是真正实现的，不是忽略掉的。

这个库是被量出来的，不是被信任的。对照 PROJ——pyproj 与 QGIS 背后的参考实现—— 从赤道到北纬 78° 的测试点上，UTM 东坐标优于 0.1 mm，北坐标优于 0.9 mm， 正算再反算的往返闭合差在几纳米量级。 EPSG 代码查询是从 EPSG 注册库程序化生成的， 不是手敲进去的，所以它的名称、单位、适用范围和投影参数都是注册库自己的。 开发者指南列出了这些精确数字，并演示如何在浏览器控制台里复现它们。

测试上用的是同一套规矩：每个计算器上线前都要在真实的浏览器文档里、 对照已确认的数值跑一遍；批量转换器对照的是手工核对过的坐标清单，而不是它自己的输出。

站点是怎么构建的

页面是手写的 HTML、CSS 和 JavaScript，不用框架、没有构建步骤， 因此在野外用手机也打得开，打开后又能离线使用。 没有登录、没有上传、没有广告、没有 Cookie；隐私政策之所以短， 是因为实在没什么可说的。计算器还支持嵌入：任一个都能用 embed=1 放进别的页面或内网，具体写在与 URL 与 JavaScript API 一起的文档里。

我们的立场

每个页面都会写明自己的假设和边界，每个计算器的页脚都带着同一句提醒： 结果仅供参考；凡涉及边界、施工放样或结算的事项，都必须由持证专业人员按适用标准复核。 这不是为自保而贴上去的法律套话，而是对一个网页计算器最诚实的描述。

凡是约定可以两立的，页面会说清它选了哪一边；凡是显示时做了舍入的， 页面会说明计算过程用的是全精度；凡是两种权威说法不一致的——两种英尺、两种墨卡托、 似大地水准面与椭球——这种分歧本身就是正文的主题，而不是脚注。

联系与勘误

算错了、解释不清、或者缺了你需要的某个单位与投影——这些都值得告诉我们， 能改的我们直接改，不去争辩。最有用的反馈请附上：你的输入、你期望的输出及其依据，以及你用的是哪个工具。

也欢迎建议新增工具，尤其是那些枯燥重复的：这里现有的计算器， 起初多半都是某个人被迫反复填的表格。 使用本站所适用的条款见使用条款。
